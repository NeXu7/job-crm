# Поиск работы — рабочее пространство

Это твоя папка с данными для Job CRM: профиль, банк фактов, истории, вопросы к интервью, резюме
и воронка откликов. Всё лежит в обычных файлах Markdown/YAML под git, поэтому любую правку видно
в истории и её можно откатить.

Приложение (`app/`) — это симлинк на код Job CRM, отдельный репозиторий. Оно читает и пишет файлы
этой папки; правки руками или через Claude Code сразу появляются в интерфейсе.

> **Это личные данные.** Здесь будут твои контакты, цифры с прошлых работ, переписка с компаниями.
> Никогда не пушь эту папку в публичный репозиторий. Если нужен бэкап — только приватный remote.

## Что где лежит

| Путь | Что это |
|---|---|
| `00-profile/profile.yaml` | Имя, контакты, образование, языки, строка позиционирования, `context` для Claude |
| `00-profile/positioning.md` | Позиционирование и нарратив: кто ты, на какие роли, почему сейчас. Строки `TODO:` — что дописать |
| `00-profile/legal-and-location.md` | Необязательный, создаёшь сам: юридическая сторона, локация, налоги — на любом языке. Если файл есть, Claude опирается на него в черновиках ответов на вопросы «Условия» |
| `00-profile/icp.yaml` | Критерии идеальной компании для оценки вакансий (fit-score) |
| `00-profile/facts/` | Банк фактов: по файлу на каждое место работы или раздел резюме |
| `00-profile/summaries.yaml` | Варианты саммари для резюме |
| `00-profile/stories.yaml` | Истории для behavioral-интервью (STAR) |
| `00-profile/questions/` | Банк вопросов к интервью по категориям, с вариантами ответов |
| `00-profile/strengths.yaml` | Сильные стороны и слабые места с заготовками ответов |
| `00-profile/notes/` | Сырьё: надиктованное и логи сессий наполнения с Claude |
| `02-pipeline/companies/` | Компании (создаются при разборе вакансии) |
| `02-pipeline/applications/` | Отклики: карточка, снимок вакансии, резюме под вакансию, подготовка |
| `02-pipeline/interviews/` | Ретро после интервью, шаблон — `_TEMPLATE.md` |
| `04-resume/recipes/` | Базовые рецепты резюме — по одному на трек (направление ролей) |
| `CLAUDE.md`, `.claude/` | Правила и навыки для Claude Code в этой папке |

## Запуск

```bash
npm --prefix app start
```

Открой http://localhost:4317. Первый запуск собирает интерфейс, это занимает несколько секунд.
Проверить, что с данными всё в порядке:

```bash
npm --prefix app run check
```

Команды запускай из этой папки: `npm --prefix app …` работает с той папкой, из которой запущен.
`npm --prefix app start` держит терминал занятым, пока работает CRM, — Claude Code открывай в другом
окне или вкладке.

Если `app/` не открывается или сервер не находит эту папку — подключи её заново из папки с кодом
Job CRM: `npm run setup -- --link <путь к этой папке>` (подробности — в README репозитория Job CRM).

## С чего начать

1. **Профиль.** «Банк фактов» → «Профиль»: имя, контакты, образование, строка позиционирования.
   Там же «Контекст поиска»: по-английски коротко опиши таймзону, локацию и готовность к переезду,
   формат найма и другие ограничения — Claude учитывает это при разборе вакансий и подготовке
   к интервью, в резюме это не попадает.
2. **Позиционирование.** Открой `00-profile/positioning.md` и ответь на вопросы в строках `TODO:`.
   Можно вместе с Claude. Эти TODO видны в CRM: «Наполнение» → «Когда-нибудь», банк «Документы».
3. **Критерии ICP.** «Банк фактов» → «Критерии ICP»: в файле стоят примеры, перепиши их под себя.
4. **Треки.** В `04-resume/recipes/` лежит один рецепт «Основной трек». Переименуй его или заведи
   несколько — по одному на каждое направление ролей, на которые откликаешься
   («Конструктор резюме» → «Сохранить как новый трек»).
5. **Банки.** Опыт, факты, истории и ответы удобнее всего наполнять с Claude Code (ниже).

## Наполнение банков с Claude Code

Открой Claude Code в этой папке и набери `/fill`. Для длинной сессии выбери Sonnet командой
`/model` — это дешевле по квоте подписки. Claude Code спрашивает разрешение на команды: просмотр
банков и проверка данных разрешены заранее (`.claude/settings.json`), запись в банки и коммит — по
твоему «да». Можно сразу указать режим:

- `/fill сырьё` — разобрать надиктованное или старое резюме;
- `/fill факты <опыт>` — факты с цифрами по одному месту работы;
- `/fill истории` — истории для behavioral по компетенциям;
- `/fill ответы motivation` — ответы на вопросы категории;
- `/fill стороны` — сильные стороны и слабые места.

Claude задаёт вопросы по одному, сначала записывает твой ответ в лог сессии
(`00-profile/notes/`), а потом черновики со ссылкой на этот лог. Цифры берутся только из твоих слов.
«Проверен» у фактов и «Готов» у ответов ставишь только ты — в CRM.

Сырьё можно сбрасывать и без Claude: «Наполнение» → «Сбросить сырьё». Надиктуй как есть, с повторами —
разберёте потом.

## Банк вопросов

В `00-profile/questions/` лежит стартовый набор типовых вопросов без ответов. Он общий — удаляй то,
что тебе не подходит, и добавляй своё. В «Профессии и технике» (`ai.yaml`) — общие вопросы о работе
в своей области и пара вопросов про AI; вопросы именно твоей профессии (код, дизайн, данные, продажи…)
добавь сам или попроси Claude Code. Вопросы про свою компанию или долгий перерыв в «Неудобных»
(`probe.yaml`) удали, если это не про тебя. Вопросы, которые реально задали на интервью, отмечай «Спросили»
в подготовке к вакансии, а хорошие новые отправляй «В банк».

## Если правишь файлы руками

Обычно всё правится в CRM; при сохранении из CRM файл переписывается целиком (с короткой шапкой
в комментарии), поэтому свои комментарии в YAML не пиши — они пропадут. Что значат поля:

- **`00-profile/profile.yaml`** — `name` (как в резюме, латиницей, если резюме на английском),
  `location` (город и страна для шапки, например «Lisbon, Portugal» или «Remote»), `contacts`
  (`email`, `phone`, `linkedin`, `github`, `website`; пустые в резюме не попадают), `education`
  (список: `id` латиницей, `school`, `field`, `degree`, `start`, `end`), `languages` (список: `name`,
  `level`, например English — C1), `positioning` (одна строка по-английски: кто ты и на какие роли
  идёшь), `context` (свободный текст по-английски для Claude, например: "Based in Lisbon, Portugal
  (UTC+0). Open to remote or hybrid in Lisbon. Employee or contractor. EU work authorization, no visa
  sponsorship needed."). Пустые `positioning` и `context` просто не попадают в запросы к Claude.
- **`00-profile/icp.yaml`** — `criteria`: `id` (латиницей; не меняй после первых разборов — по нему
  хранятся оценки в откликах), `name`, `target` (что тебе подходит: 2 балла), `reject` (что отсекаешь:
  0 баллов). Пиши конкретно: «продуктовая компания после раунда, команда 50–500» работает лучше, чем «хорошая компания».
- **`04-resume/recipes/<трек>.yaml`** — `id` (не меняй после первых откликов: на него ссылаются
  вакансии, факты и ответы), `name`, `headline` (заголовок резюме по-английски), `summary` (id из
  `00-profile/summaries.yaml`), `facts` (опыт → упорядоченный список id фактов; черновики в резюме
  не попадают), `template`, `pages`.

После ручных правок запусти `npm --prefix app run check`.

## Коммиты

Сервер сам коммитит правки из интерфейса. Claude Code коммитит свои правки с пометкой `Agent: claude`,
чтобы в журнале CRM было видно, кто что менял. Если коммиты не появляются (например, в git не заданы
имя и почта), причина видна в CRM на «Сегодня» в блоке «Окружение».
