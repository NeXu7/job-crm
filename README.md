# Job CRM

Локальное приложение для поиска работы. Работает у тебя на компьютере (`http://localhost:4317`),
данные — обычные файлы YAML/Markdown в твоей отдельной папке под git. Тяжёлую работу с текстом
(разбор вакансий, подбор вопросов к интервью, черновики ответов) делает Claude через Claude Code
CLI на твоей подписке.

Этот репозиторий — только приложение. Твоих данных в нём нет и не будет: они живут в «рабочем
пространстве», которое создаёт `npm run setup`.

## Что умеет

- **Банк фактов → резюме.** Каждое достижение — отдельный факт с цифрой, тегами, треками и
  источником. Резюме собирается из фактов по **рецепту** (какие факты, в каком порядке, заголовок,
  саммари): базовый рецепт на каждый трек, под вакансию — копия с диффом к базе. В момент отправки
  резюме **фиксируется** (lock): текст замораживается, PDF и текст для ATS-форм собираются из него
  заново. Поправил факт — поправилось везде, кроме уже отправленных резюме.
- **Вакансии по ссылке.** Вставь ссылку в любом месте интерфейса или сохрани страницу расширением
  Chrome (нужно для LinkedIn и страниц за логином). Сервер снимает страницу (у Greenhouse, Lever,
  Ashby — через их API, иначе через Chromium), а Claude заполняет компанию, требования с подходящими
  фактами из банка, красные флаги, тезисы для «почему они / почему я» и **fit-score** по твоим
  критериям ICP (0–2 за каждый).
- **Воронка с гейтами.** Стадии от «Исследую» до «Оффер». Без своих «почему они» и «почему я» карточка
  не уходит в «Готов к отклику», без зафиксированного резюме — в «Отклик». «Отметить отправленным»
  ставит follow-up через 7 дней.
- **Интервью.** Банк вопросов по категориям (знакомство, мотивация, неудобные, behavioral, лидерство,
  продукт и бизнес, профессия и техника, условия, твои вопросы к ним) с вариантами ответа под трек; банк историй STAR
  с компромиссом и выводом и матрица покрытия компетенций. В карточке отклика — **подготовка**:
  вероятные вопросы под вакансию (Claude выбирает до 12 из банка и до 8 своих), ответы под неё,
  черновики из твоих историй и фактов, шпаргалка и **тренировка** с самооценкой.
- **Наполнение банков с Claude Code.** Очередь пробелов по важности («Наполнение» в CRM). Открываешь
  Claude Code в папке рабочего пространства, набираешь `/fill` — Claude задаёт вопросы по одному,
  записывает твои ответы в лог сессии и делает из них черновики фактов, историй и ответов.
  Подтверждаешь («проверен», «готов») только ты, в CRM.
- **Журнал.** Правки из интерфейса сами коммитятся в git рабочего пространства (подряд идущие —
  одним коммитом через несколько секунд). Правки Claude Code в файлах сразу появляются в открытом
  интерфейсе.

Внутри приложения есть раздел «Как пользоваться»: сценарии от вакансии до оффера, ритм работы
и живой чек-лист первых шагов.

## Что нужно

- macOS или Linux (на Windows не проверялось).
- Node.js 22 или новее (`node -v`), git.
- [Claude Code](https://claude.com/claude-code) CLI последней версии (`claude update`) с входом через
  подписку Claude: `claude auth login`. Разбор вакансий и черновики в CRM тратят квоту этой подписки.
- Chrome — для расширения «Сохранить вакансию» (необязательно; без него вакансии с LinkedIn и других
  сайтов за логином придётся вставлять текстом вручную).

## Установка

```bash
git clone https://github.com/NeXu7/job-crm.git ~/job-crm   # репозиторий приватный: нужен доступ от автора
cd ~/job-crm
npm install
npx playwright install chromium          # браузер для снимков страниц и печати PDF
npm run setup -- ~/Documents/job-search --name "Ivan Petrov"
npm start                                # сборка интерфейса + сервер → http://localhost:4317
```

`npm start` работает, пока открыт терминал: оставь это окно открытым, в нём живёт сервер. Claude Code
запускай в другом окне или вкладке терминала. Остановить CRM — Ctrl+C.

Если `npm install` пишет про critical-уязвимость в `shell-quote` (через `concurrently`) — это пакет
только для разработки (`npm run dev`), сама CRM его не использует.

`npm run setup -- <папка>` создаёт рабочее пространство из `template/`:

- копирует шаблон: пустые банки, стартовый банк вопросов, примеры критериев ICP, `CLAUDE.md`
  и `.claude/` (правила и скилл `/fill` для Claude Code), `.gitignore`;
- с `--name "…"` записывает имя в `00-profile/profile.yaml` — так, как оно будет в шапке резюме
  (латиницей, если резюме на английском);
- делает в папке симлинк `app` → этот репозиторий, чтобы команды работали прямо из рабочего
  пространства (`/app` стоит в `.gitignore` рабочего пространства, в его git ссылка не попадает);
- пишет в `.env` этого репозитория строку `CRM_ROOT=<папка>`, остальные строки `.env` не трогает.
  По ней `npm start` в папке приложения открывает это рабочее пространство. Если там уже был другой
  путь, предупредит: прежнее рабочее пространство остаётся как было, а команды
  `npm --prefix app …`, запущенные внутри него, по-прежнему работают с ним (команда всегда берёт
  рабочее пространство, из которого запущена). Если `CRM_ROOT` задан ещё и переменной окружения,
  тоже предупредит — она важнее всего остального;
- делает `git init` (ветка `main`) и первый коммит. Если в git не заданы имя и почта, репозиторий
  создаётся без коммита, а setup печатает, что выполнить: `git config --global user.name "…"`,
  `git config --global user.email "…"` и коммит. Нет git — рабочее пространство создаётся без
  репозитория, тоже с подсказкой;
- в конце печатает следующие шаги: если не скачан Chromium для Playwright или не найден Claude Code,
  напомнит и об этом.

Setup откажется, если папка не пустая (подскажет `--link`), если это файл, если она внутри
репозитория приложения, или если параметр незнакомый.

Другие режимы:

- `npm run setup -- --link <папка>` — подключить уже существующее рабочее пространство (например,
  склонированное из твоего приватного git): ссылка `app` и `CRM_ROOT` в `.env`, данные не трогает.
  Откажется, если в папке нет `00-profile/`; предупредит, если в её `.gitignore` нет `/app` или она
  не git-репозиторий.
- `--no-env` (с любым режимом) — не трогать `.env`. Команды `npm --prefix app …` из новой папки всё
  равно работают с ней, а `npm start` в папке приложения открывает прежнюю. Нужно, чтобы попробовать
  setup, не переключая свою CRM на новую папку.
- `--template <папка>` — взять другой шаблон вместо `template/` (для разработки шаблона).

Репозиторий не перемещай после setup: симлинк `app` указывает на него по абсолютному пути
(если переместил — см. «Если что-то не так»).

## Первые шаги

1. **Профиль.** CRM → «Банк фактов» → «Профиль»: имя, контакты, образование и строка
   позиционирования (кто ты и что ищешь — Claude опирается на неё при разборе вакансий).
2. **Контекст поиска.** CRM → «Банк фактов» → «Профиль» → «Контекст поиска» (в файле — поле `context`
   в `00-profile/profile.yaml`): свободный текст на английском — часовой пояс, где живёшь и готов ли
   к релокации, формат найма (штат, EoR, контрактор), другие ограничения. Claude учитывает его при
   разборе вакансий (флаги, fit) и подготовке к интервью; в резюме он не попадает. Пусто — просто
   не учитывается.
3. **Критерии ICP.** «Банк фактов» → «Критерии ICP»: что для тебя важно в вакансии («целюсь»)
   и что отсекаешь. Claude ставит каждой вакансии 0–2 по каждому критерию, сумма — fit-score.
4. **Позиционирование.** `00-profile/positioning.md` — свободный текст: нарратив, сильные стороны,
   на какие роли идёшь. Строки с `TODO` попадают в очередь «Наполнения» (уровень «Когда-нибудь»,
   банк «Документы»). В запросы к Claude пометки `TODO` с их вопросами не уходят, текст-подсказки
   из шаблона тоже: пока документ не заполнен, Claude его не видит.
5. **Наполнение.** Открой Claude Code в папке рабочего пространства и набери `/fill`. Для длинной
   сессии выбери Sonnet командой `/model` — дешевле по квоте. Режимы: `/fill сырьё`, `/fill факты <опыт>`,
   `/fill истории`, `/fill ответы [категория]`, `/fill стороны`. Между сессиями мысли можно сбрасывать
   в CRM → «Наполнение» → «Сбросить сырьё» — Claude разберёт их первыми. Claude Code спрашивает
   разрешение на команды: просмотр банков (`bank stats/gaps/show`) и проверка данных разрешены заранее
   в `.claude/settings.json`, запись (`bank apply`) и коммит — по твоему «да»; для `npm --prefix app …`
   можно выбрать «Yes, and don't ask again».
6. **Базовое резюме.** «Конструктор»: собери рецепт для своего трека из проверенных фактов.
7. **Первая вакансия.** Вставь ссылку в любом месте страницы CRM (не в поле ввода), нажми
   «+ Вакансия» или сохрани её расширением. Через минуту-две на карточке будет разбор и fit, а во вкладке
   «Подготовка» — вероятные вопросы (это два запроса к Claude).

## Каждый день

Всё запускается из папки рабочего пространства. Команды `npm --prefix app …` работают с той папкой,
из которой запущены.

```bash
cd ~/Documents/job-search
npm --prefix app start                      # CRM → http://localhost:4317; терминал оставь открытым
# в другом окне или вкладке терминала, тоже в этой папке:
claude                                      # Claude Code с правилами и скиллами этой папки
npm --prefix app run check                  # проверить данные после ручных правок
npm --prefix app run -s bank -- gaps --level 1   # что заполнить первым (то же, что «Наполнение»)
```

Claude Code в этой папке знает устройство данных из `CLAUDE.md`: помогает с «почему они», готовит
к интервью, разбирает ретро (`02-pipeline/interviews/_TEMPLATE.md`), наполняет банки. Правила,
которые он не нарушает: не придумывает цифры (новый факт — черновик с источником и вопросом к тебе),
не трогает зафиксированные резюме, не меняет id фактов, не двигает отклики через гейты, ничего
не отправляет наружу.

## Где лежат данные и приватность

| Путь в рабочем пространстве | Что |
|---|---|
| `00-profile/profile.yaml` | Имя, локация, контакты, образование, языки, позиционирование, `context` |
| `00-profile/icp.yaml` | Критерии ICP для fit-score |
| `00-profile/positioning.md` | Позиционирование свободным текстом; строки `TODO` — пробелы в «Наполнении» |
| `00-profile/legal-and-location.md` | Необязательный, в шаблоне его нет. Твой документ про юридическую сторону, локацию и налоги, на любом языке. Если файл есть, Claude читает его для черновиков ответов на вопросы категории «Условия» |
| `00-profile/facts/<опыт>.yaml` | Банк фактов: опыт (`experience`) и факты (`facts`) |
| `00-profile/summaries.yaml` | Варианты саммари для резюме |
| `00-profile/stories.yaml` | Истории STAR и какие компетенции они покрывают |
| `00-profile/questions/<категория>.yaml` | Банк вопросов к интервью с вариантами ответа |
| `00-profile/strengths.yaml` | Сильные стороны и слабые места с ответами |
| `00-profile/notes/` | Сырьё: твои заметки и логи сессий наполнения |
| `02-pipeline/applications/<id>/` | Отклик: `application.md`, `capture/` (снимок вакансии), `resume.recipe.yaml`, `locks/`, `prep.yaml` |
| `02-pipeline/companies/<slug>.yaml` | Компании |
| `02-pipeline/interviews/` | Заметки и ретро интервью по шаблону `_TEMPLATE.md` |
| `04-resume/recipes/<трек>.yaml` | Базовые рецепты резюме, по одному на трек |
| `04-resume/build/` | Кеш PDF (собирается заново из lock) |
| `CLAUDE.md`, `.claude/` | Правила и скиллы для Claude Code |
| `app` | Симлинк на этот репозиторий |

- **Рабочее пространство — отдельный приватный git-репозиторий.** В нём твоя биография, цифры,
  контакты и переписка с компаниями. Не пушь его в публичный репозиторий. Нужна резервная копия —
  приватный remote или просто копия папки.
- **Этот репозиторий не содержит личных данных** и не читает твоих личных файлов за пределами
  рабочего пространства (кроме своего `.env`, шаблона и настроек git). Его можно форкать и присылать
  правки.
- **Что уходит в Claude.** Как в обычном разговоре с Claude на твоей подписке:
  - разбор вакансии — текст вакансии, профиль (позиционирование и контекст поиска), критерии ICP,
    названия треков и факты;
  - подбор вопросов — вакансия с разбором, профиль, тексты всех вопросов банка, истории и факты;
  - черновик ответа — вопрос и его варианты, профиль, истории, факты, `positioning.md` (для части
    категорий; без пометок `TODO` и текста шаблона), для «Условий» — `legal-and-location.md`, если он
    есть; для черновика под вакансию — ещё её разбор и твои «почему они / почему я».

  Каждая сохранённая вакансия — два запроса подряд: разбор, а за ним подбор вопросов к интервью.
  Остальное — только по кнопкам. Разборы, упавшие из-за того, что Claude CLI был не авторизован,
  повторяются сами после входа.
- Сервер слушает только `127.0.0.1` — с других устройств в сети он недоступен. Запросы, пришедшие
  не на `localhost` / `127.0.0.1` (так выглядит атака DNS rebinding — чужой домен, указывающий
  на твой компьютер), сервер отклоняет: чужая страница не прочитает твои данные.
- Изменяющие запросы к `/api` (всё, кроме GET) с чужих страниц сервер отклоняет: проходят только сам
  интерфейс (любой порт на `localhost` / `127.0.0.1`) и расширение браузера. Так посторонний сайт
  не сохранит вакансию от твоего имени и не потратит квоту.

## Обновление

```bash
cd ~/job-crm
git pull
npm install
npx playwright install chromium    # если обновилась версия Playwright; лишний раз не повредит
```

Перезапусти `npm --prefix app start` — интерфейс пересоберётся. Обновление шаблона не трогает уже
созданные рабочие пространства. Новые поля в файлах данных (например, `context` в профиле) старая
версия приложения при сохранении стирает: сначала обнови приложение, потом заполняй их. Если в новой версии поменялись правила или скиллы для Claude Code,
сравни их со своими и перенеси нужное:

```bash
diff ~/job-crm/template/_CLAUDE.md ~/Documents/job-search/CLAUDE.md
diff -r ~/job-crm/template/_claude/skills ~/Documents/job-search/.claude/skills
```

## Справочник

### Команды

В репозитории приложения (`cd ~/job-crm`) — или из рабочего пространства через `npm --prefix app …`:

| Команда | Что делает |
|---|---|
| `npm start` | Сборка интерфейса + сервер на :4317 |
| `npm run serve` | Только сервер, без пересборки интерфейса |
| `npm run dev` | Разработка: интерфейс на :5173 с горячей перезагрузкой (запросы `/api` уходят на сервер на `CRM_PORT`, по умолчанию 4317), сервер перезапускается при правках кода |
| `npm run check` | Проверка данных: схемы файлов и ссылки между банками |
| `npm run setup -- <папка> [--name "Ivan Petrov"] [--no-env]` | Новое рабочее пространство из `template/` |
| `npm run setup -- --link <папка> [--no-env]` | Подключить существующее рабочее пространство |
| `npm run check:template` | Проверка, что `template/` — корректное рабочее пространство |
| `npm run typecheck` | Проверка типов |

Инструмент банков (им пользуется Claude Code в сессии `/fill`, но можно и руками):

```bash
npm run bank -- stats                 # прогресс по банкам
npm run bank -- gaps --level 1        # что заполнить первым; --bank stories|answers|…, --limit, --json
npm run bank -- show S4               # запись и где она используется
npm run bank -- apply batch.json      # JSON-пакет операций; --dry — только проверить; - — из stdin
npm run bank -- ops                   # справка по операциям
```

`apply` проверяет пакет целиком до записи: ссылки на факты, истории, вопросы; обязательный `source`
у новых фактов и историй; статусы `verified`/`ready` не пропускает — их ставит человек в интерфейсе.
Пишет те же файлы, что и сервер; запущенная CRM подхватывает их сама.

### Claude: модели по задачам

Каждая задача идёт на своей модели, чтобы не тратить квоту зря (`src/server/config.ts`, `claudeTask`):

| Задача | Модель | Effort | Почему |
|---|---|---|---|
| `analyze` — разбор вакансии | sonnet | low | извлечение полей и сопоставление с фактами |
| `prep` — подбор вопросов | sonnet | medium | выбор из готового банка |
| `draft` — черновик ответа | opus (запасная — sonnet) | medium | текст, который ты будешь говорить вслух |

Вызов «голый»: без инструментов, MCP, скиллов, CLAUDE.md и системного промпта Claude Code.
Инструкции и стабильные данные (банк, факты, истории) идут в системный промпт и между вызовами
берутся из кэша; меняется только вакансия или вопрос. Одновременно — не больше двух вызовов.
Сохранённая вакансия — это `analyze` и сразу за ним `prep`; каждое «Переразобрать», «Подобрать
заново» и «Черновик» — ещё один запрос к модели.

### Переменные окружения

Все необязательные. Задаются в окружении или в файле `.env` в корне репозитория приложения
(переменные окружения важнее `.env`).

| Переменная | По умолчанию | Что |
|---|---|---|
| `CRM_ROOT` | из `.env` | Папка рабочего пространства. `npm run setup` пишет её в `.env` сам. Лучше полный путь; относительный в окружении считается от папки, где набрана команда, в `.env` — от папки приложения |
| `CRM_PORT` | `4317` | Порт сервера. `npm run dev` берёт его же (из окружения или `.env`); в расширении порт задаётся в его окошке |
| `CRM_AUTOCOMMIT` | `1` | `0` — не коммитить правки из интерфейса |
| `CRM_MODEL_<ЗАДАЧА>`, `CRM_EFFORT_<ЗАДАЧА>` | см. таблицу выше | Модель и effort для задачи, например `CRM_MODEL_DRAFT=sonnet` |
| `CRM_CLAUDE_MODEL` | — | Одна модель на все задачи |
| `CRM_CLAUDE_LEAN` | `1` | `0` — обычный вызов Claude Code вместо «голого» (для отладки, дороже) |
| `CRM_CLAUDE_BIN` | `claude` | Путь к Claude Code CLI |

Где искать данные, по порядку:

1. `CRM_ROOT` из переменной окружения — например, `CRM_ROOT=<папка> npm start`. Если при этом команда
   запущена внутри другого рабочего пространства, побеждает переменная, а команда предупреждает.
2. Папка, из которой запущен npm, если в ней есть `00-profile/` — `npm --prefix app …` в рабочем
   пространстве работает с ним самим, даже если в `.env` записано другое. Так `bank apply` или сервер,
   запущенные в одном рабочем пространстве, никогда не пишут в другое.
3. `CRM_ROOT` из `.env` (его пишет `npm run setup`) — например, `npm start` в папке приложения.
4. Родительская папка приложения, если в ней есть `00-profile/` (старая раскладка, когда приложение
   лежало папкой `app/` внутри данных).
5. Иначе команда не стартует и подсказывает `npm run setup`.

Если путь из `CRM_ROOT` не существует или в нём нет `00-profile/`, команда не стартует и говорит почему.

### Расширение браузера

Нужно для LinkedIn (без входа он прячет вакансию) и любых страниц за логином. Расширение берёт
страницу такой, какой ты её видишь, и отправляет в CRM на `http://localhost:<порт>`.

1. Chrome → `chrome://extensions` → включить «Режим разработчика».
2. «Загрузить распакованное» → папка `extension` в репозитории приложения
   (или `app/extension` в рабочем пространстве). Точный путь показан в CRM: «Как пользоваться» →
   «С чего начать».
3. На странице вакансии: кнопка расширения или Alt+Shift+S → «Сохранить страницу».

Порт по умолчанию — 4317. Если CRM запущена с другим `CRM_PORT`, впиши его в поле «Порт CRM»
внизу окошка расширения — он запомнится. Разрешение расширения `http://localhost/*` покрывает
любой порт на `localhost`.

### Резюме: рецепт и lock

- **Рецепт** — какие факты, в каком порядке, какой заголовок и саммари. Базовые лежат в
  `04-resume/recipes/` (по одному на трек; id рецепта — это id трека в фактах и вопросах).
  Под вакансию — рабочая копия в `applications/<id>/resume.recipe.yaml`, дифф к базе считается на лету.
- **Lock** — замороженный развёрнутый текст резюме в момент отправки
  (`applications/<id>/locks/<hash>.yaml`). PDF собирается из него заново, поэтому сами PDF не хранятся.
  Одинаковый `content_hash` значит одинаковое резюме.

### Интервью: банк вопросов и подготовка

- **Банк вопросов** — `00-profile/questions/<категория>.yaml`: формулировки, как часто спрашивают,
  для каких треков, компетенция, варианты ответа (в т. ч. под трек), истории и факты-опоры.
- **Банк историй** — `00-profile/stories.yaml`: STAR + компромисс + вывод, какие компетенции
  покрывает (1 — частично, 2 — полностью). Матрица в «Интервью → Истории» показывает дыры.
- **Подготовка к вакансии** — вкладка в карточке отклика. Список собирается на лету: вопросы,
  которые задают почти всегда, + выбор Claude (или, пока его нет, лучшие совпадения по треку и
  требованиям, не больше 12). Остальное подходящее — свёрнуто. В `prep.yaml` хранится только
  решённое: ответ под вакансию, «спросили», скрыто, выбор Claude, свои вопросы.
- **Ответ показывается** по приоритету: под вакансию → из карточки («почему они / почему я») →
  вариант банка для трека → общий вариант банка.
- **Тренировка** — вопрос → ответ вслух → заготовка → самооценка; слабые идут первыми в следующий раз.

### Гейты воронки

- В «Готов к отклику» — только с заполненными «Почему они» и «Почему я».
- В «Отклик» — только с зафиксированным резюме (lock).
- Назад и в «Закрыто» — всегда.
- «Отметить отправленным» ставит follow-up через 7 дней.

### API

`GET /api/state` — всё состояние; `GET /api/events` — SSE об изменениях; `GET /api/journal`.
Факты: `POST /api/facts`, `PUT|DELETE /api/facts/:id`, `POST|PUT|DELETE /api/experiences[/:id]`,
`POST /api/experiences/:id/order`, `PUT /api/summaries`, `PUT /api/profile` (меняет только переданные поля), `PUT /api/icp`,
`POST|PUT|DELETE /api/recipes[/:id]`.
Отклики: `POST /api/capture {url | html+url | text}`, `POST /api/applications`, `PATCH|DELETE /api/applications/:id`,
`POST …/:id/timeline`, `PUT …/:id/recipe`, `POST …/:id/lock {recipe}`, `POST …/:id/send {hash}`,
`POST …/:id/recapture`, `POST …/:id/analyze`, `POST …/:id/text {text}`,
`GET …/:id/capture/{page.html|page.md|screenshot.png|meta.json}`, `GET …/:id/locks/:hash/{pdf|text}`.
Резюме без отклика: `POST /api/resume/pdf {recipe}`, `POST /api/resume/text {recipe}`.
Наполнение: `GET /api/gaps`, `GET /api/doc-todos`, `POST /api/notes {title, text, kind}`, `GET|PUT|DELETE /api/notes/:file`,
`POST /api/sides/:kind` (`strength`|`weakness`), `PUT|DELETE /api/sides/:kind/:id`.
Интервью: `POST /api/questions {category, …}`, `PUT|DELETE /api/questions/:id`, `POST /api/questions/:id/draft {app?}`,
`POST /api/stories`, `PUT|DELETE /api/stories/:id`, `POST /api/applications/:id/prep/generate`,
`POST …/:id/prep/items`, `PUT|DELETE …/:id/prep/items/:key`, `POST …/:id/prep/items/:key/{promote|draft}`.
Claude: `POST /api/claude/check`.

## Если что-то не так

**«Не найдено рабочее пространство»** при запуске. Сервер не знает, где данные. Если рабочего
пространства ещё нет — `npm run setup -- <папка>`. Если есть — запускай из него
(`npm --prefix app start`) или подключи его: `npm run setup -- --link <папка>` в репозитории
приложения (пропишет `CRM_ROOT` в `.env`).

**«Claude: нужен вход» / «Claude CLI не найден»** внизу меню. Не найден — установи Claude Code
и проверь, что `claude` запускается в терминале (или укажи путь в `CRM_CLAUDE_BIN`). Нужен вход —
выполни `claude auth login`, затем «Проверить» внизу меню. Упавшие разборы перезапустятся сами.

**«Порт 4317 занят»** при старте. Скорее всего, CRM уже запущена в другом терминале —
открой http://localhost:4317 или останови тот процесс (`lsof -i :4317` покажет, кто держит порт).
Можно запустить на другом порту (`CRM_PORT=4318 npm start` или строка `CRM_PORT=4318` в `.env`);
тогда впиши этот порт и в окошке расширения («Порт CRM»).

**Не сохраняются вакансии или не собирается PDF**, ошибка «Не установлен браузер для сохранения
вакансий и PDF». Не скачан браузер Playwright: в репозитории приложения `npx playwright install chromium`.
На Linux могут понадобиться системные библиотеки: `npx playwright install --with-deps chromium`.

**«Страница требует входа».** LinkedIn без входа прячет вакансию. Открой её в своём Chrome
и сохрани расширением или вставь текст на вкладке «Вакансия» → «Вставить текст вручную».

**«Файлы с ошибками» на «Сегодня».** YAML сломан ручной правкой и не загружен. Запусти
`npm --prefix app run check` в рабочем пространстве — покажет файл и проблему — или попроси
Claude Code починить.

**Переместил репозиторий приложения.** Обнови симлинк и путь:
`ln -sfn /новый/путь/job-crm ~/Documents/job-search/app`. `.env` лежит в самом репозитории
и переедет вместе с ним.

**Не появляются коммиты в журнале.** Причина видна на «Сегодня» в блоке «Окружение» (и значком
внизу меню). Обычно в git не заданы имя и почта — задай `git config --global user.name "…"`
и `git config --global user.email "…"`. Ещё бывает, что папка не git-репозиторий (`git init -b main`
в ней) или лежит внутри другого git-репозитория — тогда автокоммиты выключены, сделай рабочее
пространство отдельным репозиторием. CRM замечает исправление сама, перезапуск не нужен.
